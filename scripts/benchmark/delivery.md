# Content delivery measurements

From the repository root, select an existing compatible Node/FFmpeg image (for example the image ID of the running development app) and run:

```sh
python3 scripts/benchmark/delivery.py --image <local-image-id> --output <new-results-directory>
```

Add `--verify` after the fixes to assert all matrix responses, exact bounded/suffix ranges, thumbnail MIME/ranges, authorization/missing-file responses, and forty alternating full/range cancellations. It verifies that source streams and file handles return to zero and descriptors return to baseline (allowing one socket pair still in teardown). Slow-consumer backpressure, delayed asynchronous file access and injected failures are covered separately by the focused Jest suites.

Add `--browser-image <local-Chromium-test-image-id>` to build a private production source copy and exercise the actual viewer in Chromium. The Node/FFmpeg runner and Chromium image can be the existing development app and test runner image IDs. It checks 1280px thumbnail selection/bytes, original downloads, private conditional-cache reuse, native H.264 playback and seeking, current-frame thumbnail regeneration, navigation/close, and session revocation. Browser CDP stays inside the private Docker network; no ports are published. Only task-generated storage is writable for regeneration; original fixtures stay read-only. Build/Next/browser processes and copied source/build outputs are removed. This uses `next start` with the copied production build and external read-only installed dependencies; standalone deployment packaging and deployed proxy/TLS behavior remain outside this check. The build/check container has two CPUs/3 GiB and Chromium 1 GiB, separately recorded from matrix limits.

Use `--auth-suite session` or `--auth-suite authorization` in a separate invocation to run the retained real session/race or resource-authorization checks. These create a fresh `hmv_auth_t6_fixture` database and run in its private network namespace, satisfying the suites' existing database guards. Their synthetic accounts are seeded by the suites. Do not combine this mode with the browser matrix.

This host script only orchestrates Docker and records artifacts. Application code, Prisma migrations, synthetic fixture generation and measurements run in containers. It requires installed compatible dependencies and a generated Prisma client in `home-media-viewer/node_modules`; these and source code are mounted read-only. No dependency installation or generation modifies the shared tree. Images are pinned by local image ID, the database uses the repository's pinned MariaDB image, and no host ports are published.

Each invocation starts a fresh guarded `delivery_fixture` database, applies migrations, explicitly seeds eight synthetic administrators, creates neutral FFmpeg image/video fixtures, and starts a real HTTP server using Next's Pages `apiResolver` and the actual authenticated content route. Measurement mounts for media/storage are read-only. A separate client process measures open-ended requests, bounded seeks, image navigation, same-account concurrency, distinct-account concurrency and original downloads; an additional same-account/separate-sessions scenario exercises shared account locks. Encrypted session cookies remain in memory. The padded video fixture measures byte transfer/request costs, not browser decoding or playback.

`results.json` records sample counts, statuses, requested/returned ranges and bytes, TTFB/total latency, throughput, Prisma middleware operation counts/durations, session writes, raw lock-query durations and counts classified as account shared/exclusive and session exclusive, event-loop delay, CPU/RSS, descriptors and active streams. Middleware operations are not necessarily individual SQL statements; transaction-control SQL is excluded. Raw query duration includes lock waits but does not isolate them. Cookies, query text/parameters and secrets are not recorded. Warmup excludes module loading, initial connection creation and one route request; filesystem caches are not flushed. Compare only identical fixture hashes, limits, runtime/dependency versions and request patterns, and account for host load and small sample counts.

`environment.json` records revision, tracked diff hash, pinned images, limits, limitations and cleanup. Untracked harness source is not represented by the tracked diff hash; keep the harness with the results/reviewed change. A failed command writes redacted task-only diagnostics, marks the run incomplete, and still removes its private database/network/fixtures/environment file. No images are built or tagged. No shared databases, ports, volumes or source media are changed. The default route matrix does not validate browser decoding; the optional browser mode covers that separately. Neither mode validates standalone deployment packaging, deployed reverse proxy buffering/TLS or network storage.
